# 05. 일정과 위험 요소

## 1. 일정

원래 일정은 11/15까지 환경과 PN 베이스라인을 끝내는 것이었다. 조사와 계획에 그 주를 썼으므로 구현을 뒤로 당겨 다시 잡았다. 실험 종료일(11/29)과 발표 준비 기간은 그대로다.

| 기간 | 할 일 | 끝났다는 기준 |
|---|---|---|
| 11/16~18 | 환경, PN, 테스트 (E0), 난이도 보정 (E1) | 검증 항목 통과, 주 실험 설정 확정 |
| 11/19~22 | Q-learning (E2, E3) | 학습 곡선과 정책 구조 그림. 여기까지로 발표 가능 |
| 11/23~26 | PPO (E4), 보상 ablation (E5) | 관측 2가지와 보상 4가지의 학습 결과 |
| 11/27~29 | 비교 실험 (E6), 그림 정리, 궤적 내보내기 (E7) | 실험 종료. analysis 문서 정리 |
| 11/30~12/8 | 발표자료, 언리얼 영상(선택), 리허설 | |

## 2. 계산 자원

- 클라우드 컨테이너의 CPU로 돌린다. 문제가 작아서(관측 2~6차원, 작은 신경망) GPU 없이도 가능할 것으로 본다.
- Q-learning은 한 번 학습이 분 단위로 끝날 것으로 예상한다.
- PPO는 E4와 E5를 합쳐 20회 안팎의 학습이 필요하다. 한 번에 걸리는 시간은 첫 실행에서 재고, 길면 총 스텝이나 시드 수를 줄인다.
- 컨테이너는 오래 쓰지 않으면 회수된다. 긴 학습은 중간 저장을 하고, 결과가 나오는 대로 커밋한다.

## 3. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| Q-learning이 종단 보상만으로 학습되지 않는다 | 쉬운 설정부터 시작, 유도 주기 늘리기, 역순 갱신 (`02_agents_and_rewards.md` 2절) |
| `hit_only` 보상에서 아무것도 학습되지 않는다 | 그 자체가 ablation의 결과다. 학습 곡선이 평평한 것을 그대로 보여준다 |
| 어떤 설정에서도 RL이 PN을 넘지 못한다 | 결과로 받아들인다. 질문 0과 질문 1만으로 발표를 구성하고, 왜 넘지 못했는지를 분석한다 |
| 난이도 보정에서 적당한 설정이 나오지 않는다 | 표적 기동을 키우거나($n_T$ 5 g) `bangbang` 전환 횟수를 늘린다 |
| PPO 정책이 떨린다(가속 명령이 좌우로 진동) | 제어 노력 벌점을 작은 값으로 추가하고 기록한다 |
| 학습된 정책이 PN과 전혀 다른 구조다 | 실패가 아니다. 어떤 구조인지 그림으로 보여주는 것이 분석 내용이 된다 |
| 일정이 밀린다 | `03_experiments.md` 4절의 우선순위대로 줄인다 |

## 4. 보안

회사 시뮬레이터 코드, 실제 체계의 제원, 업무에서 얻은 수치는 쓰지 않는다. 값의 출처는 공개 교재 예제 수준으로 제한하고, 문서에 "일반 값"임을 적는다.
