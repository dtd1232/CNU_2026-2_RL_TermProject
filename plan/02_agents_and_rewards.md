# 02. 에이전트와 보상

## 1. PN 베이스라인

- 명령: $a_c = N' V_c \dot\lambda$, $a_{max}$로 자른다.
- $N'$ = 3, 4, 5를 모두 평가하고, 시나리오별로 가장 좋은 값을 RL과 비교한다.
- 참고용으로 APN($N' = 3$, 표적 가속도를 정확히 안다고 가정)도 돌린다. 표적 정보를 다 알 때 도달할 수 있는 수준을 보여주는 기준이다.

## 2. Q-learning

**상태.** 정규화한 PN 요구량 $x = V_c \dot\lambda / a_{max}$를 구간으로 나눈다. PN 명령이 $N' x$이므로, 이 값 하나로 PN과 같은 정책을 표현할 수 있다.

| 단계 | 상태 | 표 크기 |
|---|---|---|
| Q1 | $x$ 21구간 | 21 × 7 = 147 |
| Q2 | $x$ 21구간 × 남은 시간 $t_{go}$ 6구간 | 126 × 7 = 882 |

- $x$ 구간은 0을 중심으로 대칭이고 0 근처가 촘촘한 로그 간격이다. 범위 밖은 양 끝 구간에 넣는다.
- Q1이 먼저다. Q2는 Q1이 끝난 뒤 "남은 시간에 따라 이득이 달라지는지"를 보기 위한 확장이다.

**기본 하이퍼파라미터.**

| 항목 | 값 |
|---|---|
| 학습률 $\alpha$ | 0.1 |
| 할인율 $\gamma$ | 0.99 |
| 탐색 $\epsilon$ | 1.0에서 0.05까지 선형 감소 |
| 에피소드 수 | 30,000 (학습 곡선을 보고 조정) |
| Q 초기값 | 0 |

**학습이 안 될 때의 대안.** 종단 보상이 200스텝 앞까지 전파되지 않으면 순서대로 시도한다.

1. 쉬운 설정(`straight`)에서 먼저 학습
2. 유도 주기를 0.1초로 늘려 에피소드 길이를 절반으로 줄임
3. 에피소드가 끝난 뒤 역순으로 갱신하거나 몬테카를로 갱신 사용

## 3. PPO

Stable-Baselines3의 `PPO`, `MlpPolicy`를 쓴다.

| 항목 | 값 |
|---|---|
| 신경망 | 은닉층 64 × 2, tanh |
| 병렬 환경 | 8개 |
| `n_steps` | 1024 |
| `batch_size` | 256 |
| `gamma` | 0.995 |
| `gae_lambda` | 0.95 |
| 학습률 | 3e-4 |
| 총 스텝 | 100만 (학습 곡선을 보고 조정) |

나머지는 SB3 기본값이다. 값은 출발점이고, 학습이 불안정할 때만 조정한다. 조정한 내용은 implementation 문서에 기록한다.

관측은 `obs_pn`과 `obs_hist` 두 가지로 각각 학습한다. 순환 정책(`RecurrentPPO`)은 `obs_hist`로 부족할 때만 쓴다.

## 4. 보상

네 가지를 정의한다. 근거는 `research/05_reward_design.md`다.

| 이름 | 종단 보상 | 스텝 보상 | 성격 |
|---|---|---|---|
| `hit_only` | 명중이면 +10, 아니면 0 | 없음 | 진짜 희소 보상 |
| `terminal` | $-\min(\text{miss}/100, 10)$, 명중이면 +10 추가 | 없음 | 끝에서만 주지만 크기 정보가 있다 |
| `potential` | `terminal`과 같음 | $\gamma\Phi(s') - \Phi(s)$, $\Phi = -R/R_0$ | 중립 셰이핑. 최적 정책을 바꾸지 않는다 |
| `los_rate` | `terminal`과 같음 | $-k\,x^2$ ($x$는 정규화한 PN 요구량) | PN 원리를 직접 넣은 셰이핑 |

- 제어 노력 벌점은 보상에 넣지 않는다. ablation을 단순하게 유지하기 위해서다. 제어 노력은 평가 지표로만 본다.
- $k$는 스텝 보상의 에피소드 합이 종단 보상과 같은 자릿수가 되도록 잡는다. 시험 실행에서 정한다.
- ablation이 아닌 실험의 기본 보상은 `terminal`이다. `terminal`로 학습이 되지 않으면 `potential`로 바꾸고 그 사실을 기록한다.
