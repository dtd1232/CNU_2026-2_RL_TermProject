# 02. 시뮬레이션 수치

코드에서 실제로 쓰는 확정 값이다. 계획 문서(`03_plan/01_environment_spec.md`)와 다르면 이 문서가 맞다. 모든 값은 교과서 예제 수준의 일반 값이고 실제 체계와 무관하다.

## 1. 교전 모델

| 항목 | 값 | 코드 위치 |
|---|---|---|
| 요격탄 속력 | 900 m/s | `SimConfig.v_m` |
| 표적 속력 | 300 m/s | `SimConfig.v_t` |
| 표적 기동 크기 | 3 g | `SimConfig.n_t_g` |
| 유도 주기 | 0.05초 (20 Hz) | `SimConfig.dt_guid` |
| 적분 | RK4, 0.005초 | `SimConfig.substeps` = 10 |
| 시간 제한 | 20초 | `SimConfig.t_max` |
| 명중 기준 | 빗나감 거리 5 m 미만 | `SimConfig.hit_radius` |
| 중력 가속도 | 9.80665 m/s² | `dynamics.G` |

## 2. 설정 프리셋

PN 난이도 보정(E1)으로 정했다. 근거는 `04_implementation/01_environment_and_pn.md` 3절이다.

| 이름 | 가속도 한계 | 유도 지연 | 성격 |
|---|---|---|---|
| `main` | 6 g | 0.25초 | 주 실험 설정. 가장 좋은 PN이 bang-bang 표적의 65%를 맞힌다 |
| `easy` | 15 g | 없음 | PN이 전부 맞힌다. 구현 검증과 첫 학습용 |
| `hard` | 4.5 g | 0.25초 | PN이 기동 표적 대부분을 놓친다. 비교 실험의 추가 조건 |

## 3. 초기 조건

| 항목 | 범위 |
|---|---|
| 초기 거리 | 8~12 km |
| 표적 진행 방향 | 정면 접근 기준 ±30° |
| 요격탄 조준 오차 | 충돌 삼각형 방향 기준 ±10° |

조준 오차는 계획의 ±20°에서 ±10°로 줄였다. ±20°에서는 가속도 한계가 낮을 때 직진 표적도 물리적으로 맞힐 수 없었다.

## 4. 표적 기동

| 이름 | 내용 | 무작위 요소 |
|---|---|---|
| `straight` | 기동 없음 | |
| `constant` | 시작 후 ±3 g 유지 | 방향, 시작 시각 0~6초 |
| `bangbang` | ±3 g, 부호 전환 | 방향, 시작 시각 0~3초, 전환 간격 1.5~4초 (두 번까지) |
| `weave` | 3 g 사인파 | 주기 2~5초, 위상 |

학습에는 `straight`, `constant`, `bangbang`을 같은 비율로 섞는다. `weave`는 평가 전용이다.

## 5. 관측 정규화

| 값 | 나누는 수 |
|---|---|
| 시선각 변화율 | 0.05 rad/s |
| 접근 속도 | 1200 m/s |
| 거리 | 12000 m |
| 리드각 | 45° |

정규화한 값은 ±5로 자른다.

- `obs_pn`: 시선각 변화율, 접근 속도
- `obs_hist`: 시선각 변화율, 접근 속도, 거리, 리드각, 직전 시선각 변화율, 직전 행동

## 6. 행동

- 연속: $[-1, 1]$. 가속도 한계를 곱한다.
- 이산: $\{-1, -\tfrac23, -\tfrac13, 0, \tfrac13, \tfrac23, 1\}$의 7단계.

## 7. 보상

| 이름 | 종단 보상 | 스텝 보상 |
|---|---|---|
| `hit_only` | 명중이면 +10 | 없음 |
| `terminal` | 100 m당 −1(최대 −10), 명중이면 +10 | 없음 |
| `potential` | `terminal`과 같음 | $\gamma\Phi(s') - \Phi(s)$, $\Phi = -R/R_0$, 종료 상태는 0 |
| `los_rate` | `terminal`과 같음 | $-k x^2$, $k = 1.0$. $x$는 PN 요구량이고 ±3으로 자른다 |
| `effort` | `terminal`과 같음 | $-k u^2$, $k = 0.05$. $u$는 가속도 한계 대비 명령 비율 |

`los_rate`의 $k$는 계획의 0.01에서 1.0으로 올렸다. `effort`는 계획에 없던 보상으로, 구현하면서 추가했다. 근거는 `04_implementation/02_q_learning.md`다.

## 8. Q-learning

| 항목 | 값 | 코드 위치 |
|---|---|---|
| 상태 (Q1) | PN 요구량 $x = V_c\dot\lambda / a_{max}$의 21구간. 0.01~1 사이를 로그 간격으로 나눈 대칭 구간 | `discretize.X_EDGES` |
| 상태 (Q2) | Q1 × 남은 시간 6구간 (경계 0.5, 1, 2, 4, 7초) | `discretize.TGO_EDGES` |
| 행동 | 7단계 | `discretize.ACTIONS` |
| 보상 | `los_rate` | `QConfig.reward_kind` |
| 학습률 | $0.5 \times 100 / (100 + n)$. $n$은 해당 상태·행동의 갱신 횟수 | `QConfig.alpha`, `alpha_n0` |
| 할인율 | 0.99 | `QConfig.gamma` |
| 탐색 | $\epsilon$ 1.0에서 0.05까지, 학습의 앞 80% 동안 선형 감소 | `QConfig.eps_*` |
| 에피소드 수 | 30,000 | `QConfig.episodes` |
| 동시 진행 에피소드 | 64 | `QConfig.batch` |
| 갱신 방식 | 상태 구간이 바뀔 때까지 행동을 유지하고 그때 갱신 | `QConfig.hold` |
| 학습 중 평가 | 512 에피소드마다, 고정된 교전 300회, 탐색 없음 | `QConfig.eval_*` |
| Q 초기값 | 0 | |
